02. Text Preprocessing

  • Task에 맞게 text를 사전에 처리하는 작업

02-01. Tokenization

  • Corpus 데이터를 token이란 단위로 나누는 작업

    • Token : 의미를 가진 단위

  • 고려사항

    1. 구두점이나 특수 문자를 단순 제외해서는 안 됨
    2. 줄임말과 단어 내 띄어쓰기가 잇는 경우
    3. 표준 tokenization 예제
      • Penn Treebank Tokenization
        1. ’ - ‘으로 구성된 단어는 하나로 유지
        2. ’ ’ ‘로 접어가 함께하는 단어는 분리

  • Word Tokenization

    • token의 기준이 word인 경우

  • Sentence Tokenization

    • token의 단위가 sentence인 경우

  • Part-of-speech tagging

    • 단어의 표기는 동일하지만, 품사에 따라 의미가 달라지는 경우

02-02. Cleaning and Normalization

  • Cleaning (정제) : 보유한 Corpus에서 Noise 제거

  • Normalization : 표현 방법이 다른 단어들을 통합시켜서 같은 단어로 만듦

  • 의의

    • 규칙에 기반한, 표기가 다른 단어들 통합
    • 대⋅소문자 통합
    • 불필요한 단어 제거
      • 등장 빈도가 적은 단어
      • 길이가 짧은 단어
    • 정규 표현식
      • Corpus 내에 계속 등장하는 글자들을 규칙에 기반해 제거

02-03. Stemming and Lemmatization

  • Corpus 내 단어 개수 감축

  • 표기는 서로 다른 단어지만, 하나의 단어로 일반화할 수 있는 경우

  • Lemmatization (표제어 추출)

    • 단어들로부터 표제어를 찾아가는 과정

      • 단어들이 다른 형태를 가져도, 뿌리 단어를 찾아가 단어 개수를 줄일 수 있는지 판단

      • 표제어 : 기본 사전형 단어

      • 추출 방법

        • 형태학적 Parsing : 형태소로부터 단어들을 만드는 학문
          • 형태소 : 의미를 가진 최소 단위
            • 어간 (stem) : 단어의 의미를 담고 있는 핵심 부분
            • 접사 (affix) : 단어에 추가적인 의미를 주는 부분

  • Stemming (어간 추출)

    • 어간을 추출하는 작업

      • 결과 단어가 사전에 존재하지 않는 단어일 수 있음

    • 한국어에서 어간 추출

      1. conjugation (동사의 활용)
        • 어간 : 용언(동사⋅형용사)을 활용할 때, 원칙적으로 모양이 변하지 않는 부분
      2. 규칙 활용
        • 어간이 어미를 취할 때, 어간의 모습이 일정한 경우
          잡다 → 잡/어간 + 다/어미
      3. 불규칙 활용
        • 어간이 어미를 취할 때, 어간의 모습이 바뀌거나 취하는 어미가 특수한 어미인 경우
          노랗/노라-, 듣/들-

02-04. Stopword

  • 데이터에서 유의미한 단어 token 선별을 위해 의미가 없는 단어 token을 제거하는 작업

    • 자주 등장하지만, 분석에 큰 도움이 되지 않는 단어
    1. NLTK에서 불용어 확인
    2. NLTK를 통해서 불용어 제거
    • 한국어에서 불용어 제거
      • tokenization 이후 조사,접속사 등 제거

02-05 Regular Expression

  • 특정한 규칙을 가진 문자열의 집합을 다루는 데 사용하는 형식 언어
  1. 정규 표현식 문법
특수문자설명
.임의의 문자 한 개
?앞 문자가 존재하거나 존재하지 않음 (문자가 0개 또는 1개)
*앞의 문자가 n개 존재하거나 존재하지 않음 (문자가 0개 또는 n개)
+앞의 문자가 최소 한 개 이상 존재 (문자가 1개 이상)
^뒤의 문자열로 문자열 시작
$앞의 문자열로 문자열이 끝남
{n}n만큼 반복
{n, m}n 이상 m 이하만큼 반복
{n,}n 이상 반복
[ ]괄호 내 문자들 중 한 개의 문자와 매치
[^문자]해당 문자를 제외한 문자 매치
{문자1}l{문자2}문자 또는 문자
문자 규칙설명
\\\\ 자체
\\d모든 숫자
\\D숫자를 제외한 모든 문자
\\s공백
\\S공백을 제외한 문자
\\w문자 또는 숫자
\\W문자 또는 숫자가 아닌 문자
  1. 정규 표현식 모듈 함수
모듈 함수설명
re.compile()정규 표현식을 compile하는 함수
re.search()문자열 전체에 대해 정규 표현식과 매치되는지 검색
re.match()문자열의 처음이 정규 표현식과 매치되는지 검색
re.split()정규표현식을 기준으로 문자열을 분리해 list로 return
re.findall()문자열에서 정규 표현식과 매치되는 모든 경우의 문자열을 list로 return
re.finditer()문자열에서 정규 표현식과 매치되는 모든 경우 문자열에 대한 iterater return
re.sub()문자열에서 정규 표현식과 일치한 부분에 대해 다른 문자열로 대체
  1. 정규 표현식을 이용한 tokenization
    • RegexpTokeinzer() : 괄호 안에 하나의 토큰으로 규정하기 원하는 정규 표현식을 넣어 tokenization 수행

02-06. Integer Encoding

  • 컴퓨터는 text보다 숫자를 더 잘 처리하므로, NLP에서 text를 숫자로 바꾸는 기법들이 존재

  1. Integer Encoding

    • 단어를 frequency 순으로 정렬한 vocabulary(단어 집합)을 만듦

      • 높은 frequency 순서대로 차례로 낮은 숫자의 정수 부여

    • OOV (Out-Of-Vocabulary)

      • Vocabulary에 존재하지 않는 단어가 생기는 현상
        • frequency가 높은 n개의 단어만 남길 때, 전체 단어 집합에서 사라지는 단어 발생

  2. Keras text preprocessing

    • from tensorflow.keras.preprocessing.text import Tokenizer

02-07. Padding

  • NLP 중, 각 문장의 길이가 서로 다른 경우가 존재함

    • 길이가 동일한 문서들을 하나의 행렬로 묶어서 처리 가능

      • 반드시 가장 긴 문서를 기준으로 할 필요는 없음
        • 단, 데이터 손실 발생

    • 보통 0을 Padding 값으로 사용

    • ex) ```
      preprocessed_sentences = [
      [‘barber’, ‘person’], [‘barber’, ‘good’, ‘person’],
      [‘barber’, ‘huge’, ‘person’], [‘knew’, ‘secret’],
      [‘secret’, ‘kept’, ‘huge’, ‘secret’], [‘huge’, ‘secret’],
      [‘barber’, ‘kept’, ‘word’], [‘barber’, ‘kept’, ‘word’],
      [‘barber’, ‘kept’, ‘secret’],
      [‘keeping’, ‘keeping’, ‘huge’, ‘secret’, ‘driving’, ‘barber’, ‘crazy’],
      [‘barber’, ‘went’, ‘huge’, ‘mountain’]
      ]

      '''
      각 단어를 frequncy에 따라 변환
      가장 많이 나온 단어가 1부터 오름차순
      '''
      → [[1, 5], [1, 8, 5], [1, 3, 5], [9, 2], [2, 4, 3, 2], [3, 2], [1, 4, 6], [1, 4, 6], [1, 4, 2], [7, 7, 3, 2, 10, 1, 11], [1, 12, 3, 13]]

      '''
      0을 Padding으로 넣어 모든 문장의 길이를 가장 긴 문장과 동일하게 맞춰 행렬 하나로 변환.
      예시는 numpy
      '''
      → array([[ 1, 5, 0, 0, 0, 0, 0], [ 1, 8, 5, 0, 0, 0, 0], [ 1, 3, 5, 0, 0, 0, 0], [ 9, 2, 0, 0, 0, 0, 0], [ 2, 4, 3, 2, 0, 0, 0], [ 3, 2, 0, 0, 0, 0, 0], [ 1, 4, 6, 0, 0, 0, 0], [ 1, 4, 6, 0, 0, 0, 0], [ 1, 4, 2, 0, 0, 0, 0], [ 7, 7, 3, 2, 10, 1, 11], [ 1, 12, 3, 13, 0, 0, 0]])```

  1. Numpy로 Padding 삽입

    • 문장 뒤에 padding 삽입

  2. Kears Preprocessing 도구로 Padding 삽입

    • 문장 앞에 padding 삽입

02-08 One-Hot Encoding

  • Vocabulary 크기를 Vector 차원으로 하고, 표현하고자 하는 단어의 index에 1을 부여하고,
    다른 index에는 0을 부여하는 단어의 Vector 표현 방식

    • 이렇게 표현된 Vector를 One-Hot vector라고 함

    • 단어를 표현하는 가장 기본적인 방법

    • 과정

      1. Integer Encoding (각 단어에 고유한 정수 부여)
      2. 표현하고자 하는 단어의 정수를 index로 간주해 1, 다른 index엔 0 부여

    • 한계

      • 단어의 개수가 늘어날 수록 Vector 저장을 위한 공간 즉, 차원이 계속 늘어남
      • 단어의 유사도를 표현하지 못함
        • 해결 방법
          1. Count 기반 Vectorization. LSA, HAL 등
          2. 예측 기반 Vectorization. NNLM, RNNLM, Word2Vec, FastText 등
  1. Keras를 통한 One-Hot Encoding
    • to_categorical()

    • Cohesion Probability (응집 확률)

      • Substring (내부 문자열)이 얼마나 응집해 자주 등장하는지 판단하는 척도

        • 값이 높을수록 전체 corpus에서 이 문자열 시퀀스는 하나의 단어로 등장할 확률이 높음
        • 현재까지 문자열이 등장했을 때, 다음 문자가 붙어서 더 긴 문자열이 될 확률

      • cohesion(n)=(∏i=1n−1​P(ci+1​∣ci​))n−11​

        • c : 분석 대상 문자열을 구성하는 문자
          • ci​ : 문자열의 i번째 문자
          • c1:i​ : 첫 번째 문자부터 i번째 문자까지 부분 문자열
          • c1:i+1​ : c1:i​ 에 Ci+1​을 붙인 부분 문자열
        • n : 분석 대상 문자열의 전체 문자 개수
        • i : 문자열을 앞에서부터 확장할 때 사용하는 index
        • P(A∣B) : B가 등장했을 때 A까지 이어질 조건부 확률
        • ∏ : 여러 확률을 차례대로 곱합
        • n−11​ : 곱한 n−1개 확률에 대한 기하 평균 계산을 위한 지수
      1. 문자열을 문자 단위로 분리해 내부 문자열을 만듦
      2. 왼쪽부터 문자를 추가해 각 문자열이 주어졌을 때 다음 문자가 나올 확률 계산
      3. 누적곱

    • Branching Entropy

      • 주어진 문자열 다음에 나오는 문자가 얼마나 다양한지 판단하는 척도
        • 높을 수록 더 다양한 문자가 나올 수 있음

    • L tokenizer

      • L token + R token으로 나누되, 점수가 가장 높은 L token을 찾음
        • L token : 단어의 핵심 의미를 가진 앞부분
        • R token : 조사⋅어미처럼 뒤에 붙는 부분

    • 최대 점수 tokenizer

      • 띄어쓰기가 되지 않는 문장에서, 점수가 높은 글자 시퀀스를 순차적으로 찾는 tokenizer

    • 반복되는 문자 정제

      • 반복되는 문자열은 하나로 정규화
