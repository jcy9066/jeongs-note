RL 실습 - PyBullet_drone

2026년 9월 18일15 min read

  • ReinforcementLearning
  • Practice

| 참고 : https://github.com/learnsyslab/gym-pybullet-drones, https://wandb.ai/jcy9066_wandb/gym-pybullet-drones-pointreach/workspace?nw=nwuserjcy9066

learn.py

  • PyBullet Drone Hover 환경에서 PPO를 학습시키는 예제
    | 참고 : PPO

  • 환경 생성 → PPO 학습 → 주기적 평가 ⋅ best model 저장 → 학습된 policy 실행

    • 즉, RL 학습 파이프라인을 한 파일에서 보여주는 최소 예제

  • Multiagent

    • 한 환경에서 여러 대의 Drone을 동시에 사용할지 선택하는 옵션
    • DEFAULT_AGENTS = n
    • DEFAULT_MA = {boolean}

  • stable-baselines3 (SB3)

    • Python용 RL 알고리즘 라이브러리

  • logger

    • 학습⋅시뮬레이션 data를 기록하고 나중에 분석하기 위한 도구

  • hoveraviary

    • 목표 위치에서 hovering하도록 학습하는 RL 환경

  • ObservationType

    1. kin
      • kinematic state를 observation으로 사용
        ex) position, pose, linear⋅angular velocity
    2. rgb
      • camera의 RGB 이미지를 observation으로 사용

  • ActionType

    1. rpm : 4개 모터의 RPM을 각각 조절
    2. pid : goal position을 주고, PID가 RPM 계산
      | 참고 : PID
    3. vel : goal velocity를 주고, PID가 RPM 계산
    4. one_d_rpm : 값 1개로 4개 모터 RPM을 동일하게 조절
    5. one_d_pid : 값 1개로 z축 목표 위치만 조절

  • train_env

    • Data 수집 및 Policy를 업데이트하는 학습용 환경

  • eval_env

    • Policy 성능을 별도로 측정하는 평가용 환경

  • test_env

    • 최종 성능 테스트

  • **model = PPO({policy_name}, {env}, {verbose})

    • PPO 알고리즘 사용
    • policy_name : 사용할 network
    • env : 학습 환경
      ex) train
    • verbose → 1 : 학습 로그 출력

  • target_reward = {n}

    • 학습 성능이 충분히 좋아졌다고 판단할 기준 reward
    • single-agent와 multi-agent에 따라 기준값이 다름
      • ∵ 각 drone reward의 총합 reward를 사용하므로
    • action type에 따라 기준값이 다름
    • reward 설정 기준
      • 환경의 이론적 최대 reward
      • task 성공 조건 기준
      • baseline 성능 기준
      • 여러 실험을 통한 threshold

  • callback_on_best

    • 평가 reward가 target_reward를 넘으면 학습 종료
    • eval_callback : 새로운 최고 성능이 나오면 실행

  • 일정 간격 Eval

  • 학습
  • 최종 test

    • 재현성과 안정성이 중요한 경우, 원인을 확인해야 함

HoverAviary

  • Hover RL 문제 정의

    • 즉, Agent가 어떤 문제를 풀어야 하는지 정의한 파일

  • Goal Position, Reward, 성공⋅실패 조건, 실패⋅시간 초과 조건 구현

  • init

    • self.TARGET_POS : 목표 위치
    • self.EPISODE_LEN_SEC : episode 길이

  • _computeReward()

    • 현재 position과 goal position 사이 거리로 reward 계산
  • _computeTerminated()
    • episode terminated condition
    • goal position에 도달하면 episode를 성공으로 종료
  • _computeTruncated()
    • 실패 조건이나, 시간 제한으로 중단되는 종료 조건
  • _computeInfo()
    • 환경이 Agent에게 observation, reward, 종료 여부 외의 추가적인 진단⋅분석 정보를 전달하기 위한 dictionary

BaseRLAviary.py

  • 여러 RL Task가 공통으로 사용하는 기반 class

  • init

    • self.ACTION_BUFFER_SIZE : action buffer. observation에 최근 action history를 포함시키기 위함
      → 최근 제어 명령도 확인 후 판단

    • self.OBS_TYPE = obs : 현재 observation 방식 저장.
      ex) KIN, RGB

    • self.ACT_TYPE = act : action을 어떤 의미로 해석할지

    • self.ctrl

      • drone마다 PID Controller를 하나씩 생성
        | 참고 : PID

    • SPEED_LIMIT

      • velocity action용 최대 속도 설정
      • Action 범위를 현실적이고 안정적인 수준으로 제한하기 위함

  • _actionSpace()

    • Agent가 출력할 Action의 차원과 허용 범위를 정의
    • self.ACT_TYPE
    • Action 범위를 정규화된 범위로 사용함
      → 여기선 [-1, 1]

  • _observationSpace()

    • Agent가 받는 Observation의 형태와 값 범위를 정의하는 함수
      • kin은 기본적으로 12차원 State + Action History 추가

  • _computeObs()

    • 현재 drone 상태를 읽어 실제 observation verctor를 만들어 변환하는 함수
    • obs = self._getDroneStateVector(i)

BaseAviary.py

  • RL과 무관한 공통 시뮬레이션 기능
    ex) Drone 생성, 물리 시뮬레이션 step, State 업데이트, collision⋅physics 처리 등

  • step()

    • PPO가 낸 값을, 시뮬레이터가 실제 사용할 수 있는 모터 명령으로 바꾸는 과정

  • for _ in range(self.PYB_STEPS_PER_CTRL)

    • 실제 physics 시뮬레이션 진행
    • 한 번의 RL control step 안에서, physics를 여러 번 돌릴 수 있음
      • agent의 control 명령 주기보다, 실제 물체의 움직임을 더 촘촘하게 계산해야 시뮬레이션이 안정적임

  • self._updateAndStoreKinematicInformation()

    • physics 계산 후, 변화된 drone의 최신 state를 읽는 단계

  • self.step_counter

    • 시뮬레이션 시간이 얼마나 진행되었는지 추적하기 위한 값
    • self.step_counter = self.step_counter + self.PYB_STEPS_PER_CTRL

  • _physics(self, rmp, nth_drone)

    • RPM을 물리적인 힘과 torque로 바꾸는 부분

  • z_torque

    • z_torque = (-torques[0] + torques[1] - torques[2] + torques[3])
      • motor 0, 2는 반시계 방향으로 돌기 때문에, -를 붙임

  • p.stepSimulation(physicasClientId=self.CLIENT)

    • PyBullet이 State를 갱신하는 단계
    • 적용된 힘과 torque를 바탕으로 drone의 다음 물리 state를 계산

  • reset(self, seed, option)

    • Episode 종료 시, 새 Episode 시작 state로 되돌리는 함수

    • p.resetSimulation(physicsClientId=self.CLEINT)

      • PyBullet simulation 전체 초기화
      • 기존 drone⋅물체 state 제거

    • self._housekeeping()

      • drone 다시 생성
      • 초기 position⋅pose 설정
      • step_counter 초기화
      • 이전 action ⋅ state 관련 변수 초기화

    • self._updateAndStoreKinematicInformation()

      • 초기 drone의 position, velocity, pose 등을 읽어 저장

    • initial_obs = self._computeObs()
      initial_info = self._computeInfo()

      • 새 Episode의 최초 observation과 info 생성

  • _housekeeping()

    • 초기 변수 ⋅ State 초기화
  • _updateAndStoreKinematicInformation()
    • 현재 drone state를 읽어서 class 변수에 저장

ppo.py

| 참고 : PPO

  • Stable-Baselines3 내부 PPO

  • train()

    • 현재 Policy에 Rollout에서 저장된 Observation과 Action을 다시 넣어서 value, log_prob, entropy를 계산함
      • value : Critic이 예측한 V(s)
      • log_prob : 현재 Policy가 action을 선택할 log 확률 logπθ​(a∣s)
      • entropy : Policy의 무작위성 정도
  • Advantage 정규화, Policy Ratio 계산
    • Advantage를 평균 0, 표준편차 1로 정규화
    • PPO 업데이트의 Gradient Scale 안정화
  • Clipped Surrogate Objective
  • Value Loss
    • Actor, Critic 학습
  • Entropy Loss
    • Policy Exploration 정도를 유지하기 위한 항
  • KL Divergence
    | 참고 : KL Divergence
    • KL Divergence를 이용한 과도한 Policy 업데이트 감시
  • Gradient 계산, Parameter 업데이트

RL에서 어떤 식으로 Agent를 학습시켜야 하는가

  • Agent 학습의 문제가 무엇인지 진단하고, 해당 부분만 수정하는 방식

    • 즉, Bottleneck을 찾아 하나씩 제거하는 방식

  • 핵심

    • Reward 설계
    • Policy 개선

  • 순서

    1. Task 정의 (고정)
    2. Observation ⋅ Action 설계
    3. Reward ⋅ Termination
    4. Algorithm 선택
    5. Hyperparameter tuning
    6. Generalization ⋅ Robustness

  • 표준 흐름

    1. Task 정의
    2. Observation ⋅ Action ⋅ Reward 설계
    3. Baseline 학습
    4. 공통 평가 지표로 성능 확인
    5. 실패 원인 ⋅ bottleneck 진단
    6. 한 요소씩 수정
    7. ablation 또는 hyperparameter tuning
    8. 여러 seed로 재검증
    9. randomization ⋅ robustness 평가
