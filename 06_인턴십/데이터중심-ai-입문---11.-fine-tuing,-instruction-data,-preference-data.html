데이터중심 AI 입문 - 11. Fine-tuing, Instruction Data, Preference Data

데이터중심 AI 입문 - 11. Fine-tuing, Instruction Data, Preference Data

2026년 9월 01일16 min read

  • DeepLearning
  • Lecture
  • fine-tuning의 장점
    • Pre-train에 비해 필요한 컴퓨팅 자원이 적음
    • PEFT (Parameter-Efficient Fine Tuning)
      • Pre-trained LLM 내 대부분의 parameter를 freezing하고 일부만 fine-tuning

Fine-Tuning

  • Downstream Task를 해결하기 위해, Pre-trained model에 추가적인 train을 진행하는 것

  • 개요

    • LLM에서 pre-train은 대규모 text를 수집하고, 다음 단어를 예측하는 성능을 높이는 방식

      • 그러나 사람들은, AI Assistant를 기대하면서 LLM을 사용함
        • 이 격차를 해소하기 위해 Pre-trained model을 조정하는 방법

    • ICL (In-Context Learning)

      • Prompt 안에 Example이나 Instruction을 제공해 새로운 input을 처리하게 하는 방식

      • GPT-3 논문에서 제안된 방법

      • Pre-trained LLM에 대해 Task 설명, 구체적인 질문과 답변 sample을 input으로 제공해 모델이 Task를 이해하고 올바른 답변을 생성하도록 함

      • 장점

        • 모델의 parameter를 업데이트하지 않고도, input text를 어떻게 설계하느냐에 따라 동작을 제어하고, 소량의 sample로 다양한 task를 해결할 수 있음

      • 단점

        • Zero-shot Learning 성능이 극도로 낮음
        • 성능이 Sample에 크게 의존함
          • sample 수가 적은 경우
          • sample 내용이나 순서가 다른 경우
        • Sample 수에 제한이 존재함
          • 최대 input 길이 제한이 있음

    • Instruction Tuning

      • 다양한 Task의 Dataset를 Instruction과 Response 형식으로 통일하고, Supervised Learning으로 parameter를 업데이트하는 기법

        • Instruction과 Response Pair를 학습해 범용적인 성능을 갖게 됨

      • ICL의 문제를 해결하기 위해 제안된 방법

      • 장점

        • 다양하고 자연스러운 응답을 생성함

      • 단점

        • 부정확하고 잘못된 정보를 기반으로 한 응답을 할 수 있음
        • 편견, 차별, 불법 행위를 조장하는 응답을 할 수 있음

    • RLHF (Reinforcement Learning from Human Feedback)

      • 인간 feedback을 활용한 강화학습
      • 지시에 대해 생성된 여러 응답을 사람이 평가하고, 이를 활용해 모델을 fine-tuning
        • 모델의 output을 사람의 선호에 더 가깝게 만들고자 함
          • Preference Tuning인 DPO, IPO 등 제안
            • DPO (Direct Preference Optimization)
              • 선호 응답이 비선호 응답보다 더 높은 확률을 갖도록 LLM 최적화 (Reward Model, RL 없이)
            • IPO (Identify Preference Optimization)
              • 선호 pair의 차이를 일저안 목표 수준으로 맞추도록 최적화 하는 방법

Instruction Data

  • Instruction tuning을 수행하기 위해 instruction과 response로 구성된 Instruction Data가 필요

    • Instruction : 사용자가 LLM에 Task를 전달하기 위한 문장
    • Ideal Response : 사용자가 지시에 대해 생성을 바라는 문장

  • 좋은 Instruction Data

    • Response Quality, Instruction Diversity, Instruction Complexity 관점이 중요함

    • Response Quality

      • 고품질 Response 특징

        • Instruction의 의도를 정확하게 인지하고, 적절히 답변
        • 너무 짧거나 길지 않고 적절한 길이를 가짐
        • 지시가 윤리적, 도덕적 관점에서 부적절한 경우, 응답을 거부할 수 있음

      • 저품질 Response 특징

        • 지시의 의도를 이해하지 못하고, 전혀 맞지 않는 대답을 함
        • 공격적이거나 차별적인 표현이 포함됨
        • 부정확한 정보를 포함함

      • Superficial Alignment Hypothesis

        • LLM이 지닌 지식과 능력은, Pre-train에서 획득된다는 가설 (Zhou 등 제안)
        • Instruction Tuning은, 대화의 스타일을 습득하기 위한 과정이며, Instruction Data는 소량이어도 모델의 성능을 충분히 향상 시킬 수 있다고 주장함

      • Instruction Mining

        • Instruction Data의 Quality를 추정해, 고품질 데이터 선별 (Cao 등 제안)

    • Instruction Diversity

      • Instruction Data에 포함된 Task의 종류를 늘려, Diversity를 높이면 모델 성능이 향상됨

      • 반면, 단순히 각 Task에 대한 Data 수를 늘리면 성능이 크게 개선되지 않았음

      • InsTag

        • Instruction에 의도와 의미를 tag로 표현해, SFT data의 Diversity와 Complexity를 측정하고, 좋은 train data를 선택하는 방법
          • SFT (Supervised Fine-tuning Data) : 모델이 볼 정답이 포함된 예시 train data

    • Instruction Complexity

      • Instruction Data 내 Instruction Complelxity는 모델 성능이 큰 영향을 미침

      • Evol Complexity

        • Instruction Data의 Complexity를 5단계로 평가하고, 데이터 선별을 위한 Complexity 예측 모델을 구성함 (Liu 등 제안)
        • 복잡도가 높은 데이터를 우선 선택

  • 기존 데이터를 활용한 Dataset 제작

    • 대규모 Dataset에, 각 Task에 맞는 template을 적용해 Instruction Data를 구축함

    • Flan Collection

      • 여러 NLP Task를 Instruction-Response 형식으로 모은 Dataset

    • xP3 (Crossligual Public Pool of Prompts)

      • 여러 언어로 구성된 Instruction Data를 모은 Dataset

      • 장점

        • 낮은 비용
        • NLP 처리 관련 Data의 수월한 확보

      • 단점

        • 부자연스러운 데이터
        • Diversity 부족

  • 사람에 의한 Dataset 작성

    • 이미 존재하는 Dataset으로 Instruction Data를 구축하면, Quality와 Diversity를 보장하기 어려웠음

      • 따라서 사람이 직접 Instruction Data를 작성하고자 함

    • 유의점

      • 명확한 가이드라인 설정

        • 일관성 있는 data를 위해, Response에 대한 구체적인 가이드라인이 있어야 함

      • 적절한 Annotator의 채용

        • 전문 지식이 요구될 때는, 해당 분야에 해박한 사람을 고용해야 함

      • 적절한 Task 할당

        • Annotator별로, Task를 적절히 분배하고, Instruction의 종류나 Response 난이도가 한쪽으로 치우치지 않아야 함

      • 지속적인 품질 관리

        • 정기적인 평가와 확인이 필요

    • databricks-dolly-15k

      • 임직원들이 작성한 15,000건 이상의 Instruction과 Response로 구성된 data

      • 총 8개의 범주로 나눠짐

      • 특징

        1. 임직원에 의한 Annotation
        2. Gamification 도입
          • Gamification : 게임 요소를 적용해, 참여와 동기를 높이는 방식

    • OpenAssistant Conversations Dataset

      • 자원봉사자들의 Crowdsourcing을 통해 수집된 Dataset

        • Crowdsourcing : 대중이 참여해 만들어나가는 프로세스

      • 특징

        • Annotation Task 분리
          • Instruciton 단계와 Response 단계를 나누어, 단계별로 Task 할당
        • Quality 관리
        • 해야 할 일 (DO)와 하지 말아야 할 일 (Don’t)를 구체적으로 기술함

      • 장점

        • 고품질 데이터 확보 가능
        • 목적에 맞는 데이터 수집
        • 전문적인 Domain 대응

      • 단점

        • 높은 비용
        • 품질 관리의 어려움

  • LLM을 활용한 Dataset

    • 사람이 직접 Instruction Data를 구축하려면, 많은 시간과 비용이 듦
      • 고성능 LLM을 통해 Instruction Data를 효율적으로 수집 및 작성하는 방법이 주목받고 있음

    1. 사람과 LLM 간 대화를 그대로 Instruction Data로 활용하는 방식

      • Usecase에 근거한 Instruction을 얻을 수 있음
        • Usecase : 사용자가 시스템이나 모델을 어떤 목적과 방식으로 사용하는지 나타내는 활용 사례

    2. LLM으로 Instruction과 Response를 모두 생성해 Instruciton Data를 만드는 방식

      • Self-Instruct

        • 사람이 작성한 n개의 Instruction을 준비하고, 이를 저장할 Task Pool을 만듦
        • Pool에서 무작위로 m개를 뽑아 Few-shot Learning Sample로 제시해 Instruction 생성
        • 생성된 데이터를 Filtering, Postprocessing한 뒤, 다시 Task Pool에 추가

      • Evol-Instruct

        • LLM을 통해 다양하고 복잡한 내용으로 구성된 Instruction Data를 생성하기 위해 개발된 방법

        • 특징

          • Diversity와 Complexity를 높이기 위해, 초기 Instruction을 In-Depth Evolving과 In-Breath Evolving 방식으로 Evolving 시킴
            • Evolving : LLM으로 Instruction을 변형해 더 다양하거나 복잡하게 발전시키는 과정

        1. In-Depth Evolving

          • 주어진 Instruction을 더 복잡하게 바꾸는 기법
          1. Add Constraints : 원래 Instruction에 제약 조건이나 요구 사항 추가
          2. Deepening : 내용을 더 깊게 파고들어, Complexity를 늘림
          3. Concretizing : 추상적인 개념을 더 구체적으로 치환
          4. Increase Reasoning : Instruction 해결을 위한 추론 단계 수 증가
          5. Complicate Input : Instruction에 XML, table 등 복잡한 input 추가

        2. In-Breath Evolving

          • LLM으로 주어진 Instruction과 전혀 다른 유형의 Instruction을 생성해 Diversity를 높이는 작업

      • Instruction BackTransition

        • 웹에 존재하는 text에서 Response를 만든 뒤, Response에서 Instruction을 다시 만들어 Instruction Data를 생성하는 방법

        1. Self-Augmentation

          • 웹 Corpus에서 Instruction Data를 만듦
            • Corpus : 연구 목적으로 정리한 단어 집단
          1. Seed Data를 준비함
            • Seed Data : 고품질의 Instruction Data
          2. Response y가 주어졌을 때, Instruction x를 출력하는 Backward 모델 Myx​:=p(x∣y)를 구축
            • Backward Model : 정답이 주어졌을 때, input을 생성하는 모델
          3. 웹에서 수집한 text yi​를 Response로 삼아, 모델 Myx​에 입력해 Instructoin xu​를 생성함
            → InstructionDataA:={x^i​,yi​}

        2. Self-Curation

          • 앞서 생성한 Instruction Data A에 Quality가 높은 data를 추출하는 것이 목적
          1. Seed Data만 이용해 Instruction Tuning한 모델 Mo​를 구축
          2. InstructionDataA를 Mo​로 5단계로 평가해, score ai​를 측정
          3. ai​가 threshold k 이상인 pair만 선별해 고품질의 Instruction Data Akn​을 얻음
    • 장점
      • 고속 구축 가능 : 사람보다 훨씬 빠르고 대량으로 구축할 수 있음
      • 낮은 비용
    • 단점
      • 이용 약관에 따른 제약
      • 낮은 데이터 신뢰도
      • Data Quality가 LLM에 의존

Preference Data

  • Instruction에 대한 여러 Response의 선호도를 매긴 Data를 만들어 train에 사용하는 방식

    • 단, 더 선호되는 Response가 무엇인지 명확하지 않음

    • Helpfulness와 Safety를 기준으로 설정한 data

    • 개발자가 생각하는, 선호되는 Response에 대한 명확한 정의를 세워야 함

      • HHH 기준

        • 3가지를 충족하면, 사람이 선호하는 모델 (Anthropic이 제안)
        1. Helpful : 사용자 지시나 질문을 정확히 이해하고, 간결하고 유용한 답변 제공
        2. Honest : 제공하는 정보에 거짓이나 오류가 없도록 주의
        3. Harmless : 공격적 및 차별적인 발언을 하지 않음

      • Model Spec

        • 모델이 어떤 행동을 해야할 지에 대한 규정 (OpenAI의 기준)
        1. Objectives : 모델의 바람직한 행동 방향 제시
        2. Rules : 2가지 이상의 목적이 상충될 때, 어느 목적을 우선시할지 정한 규칙
        3. Defaults : 최종 판단은 개발자나 사용자에게 맡기는 항목

  • 작성 방법

    • 어떤 Instruction가, 생성된 여러 Response와 어느 쪽이 우수한 지 정보를 포함해 구성
      1. 사람 또는 LLM을 활용해, 폭넓은 난이도를 갖춘 Instruction 수집
      2. 여러 Response를 생성한 뒤, 서로 간의 우열을 부여하는 정보 추가
        1. Ranking
          • Annotator가 여러 개의 Response를 가장 뛰어나다고 생각하는 순서대로 늫는 방법
        2. Voting
          • Annotator와 model의 다수결로 응답을 결정
        3. Scoring
          • Annotator나 Regression Model을 이용해 각 Response에 점수를 부여하지 않고, 대소 관계를 바탕으로 우열 관계 파악

  • Annotator의 참여로 발생하는 문제와 대응 방안

    1. 편향
    2. 부담 : 유해한 문장을 포함하는 Response의 우열을 가리므로 스트레스를 받을 수 있음
    3. 난이도 상승 : LLM 성능 향상에 따라, Response의 우열을 정확히 가리기 어려움

  • Dataset

    • hh-rlhf (Anthropic Helpfulness and Harmlessness Dataset)

      • Helpfulness와 Harmlessness 관점에서 작성한 Preference Data
      • Crowd Worker가 LLM과 대화를 주고 받으며 구축함
        • Crowd Worker : 다수의 작업자
        • Likert Scale에 따라, 8단계로 평가
          • Likert Scale : 설문조사 방식

    • UltraFeedback

      • GPT-4를 활용해 작성된 대규모 Preference Data
      • 각 Response에 대해 2가지 Feedback 제공

      1. Response에 대한 점수

        • 아래 4가지 요소에 기반한 점수
        1. Folllow Instruction : 지시 준수도
        2. Helpful and Informative : 유용성 및 정보 풍부도
        3. Truthful : 신뢰성
        4. Honesty : 정직성

      2. Response에 대한 서술형 Feedback

        • Feedback을 토대로, Response에 비평하는 UltraCM 모델을 만듦
          • UltraFeedback
            1. 여러 Dataset에서 Instruction sampling
            2. 서비스 형태로 제공되는 모델과 공개된 모델 중 4개를 무작위로 선택해 각 Instruction에 대한 Response 생성
            3. Response에 대해, GPT-4를 사용해 앞선 4가지 항목 점수 부여

    • SHP-2

      • 약 480만 건의 Preference Data로 이루어진 Dataset
        • SNS, QA 웹사이트에서 Scraping한 글, 댓글, 투표 등에 대한 data를 수집함
